## 서비스·Worker 확장 방향

CLI와 향후 FastAPI 모두 같은 서비스의 명령을 호출하게 유지합니다. HTTP 요청은 작업 생성·제어 요청만 기록하고 즉시 반환하며 장시간 Runner 호출을 요청 처리에 포함하지 않습니다. 현재 start(detached=False)는 대기하는 호출이므로 HTTP에서 그대로 사용하면 안 됩니다.

Worker는 작업의 claim/lease·heartbeat·예상 상태와 버전을 확인한 뒤 사전 점검을 포함한 실행을 소유해야 합니다. 현재의 실행별 프로세스와 OS 잠금은 유용한 기반이지만, 큐 대기 취소·사전 오류·중복 사전 점검을 포함한 계약을 보강해야 합니다. 원격/분산 큐 프레임워크를 지금 도입할 필요는 없습니다.

상태 이벤트는 `event_id`, `run_id`, `step_id`, 회차, 유형, 시각, 버전 있는 payload를 갖도록 설계합니다. 로그는 회차·시도·오프셋을 포함한 커서로 조회하고 SSE는 저장된 이벤트의 재생 어댑터로 둡니다. 명령 요청·수락·실제 종료를 구분해 취소 버튼을 누르자마자 종료된 것처럼 표시하지 않습니다.

승인 응답은 승인한 SHA와 증거 묶음을 반환해야 합니다. 과거 승인 이력과 현재 브랜치 상태를 구분하고 Worktree 정리 여부와 무관하게 유효성을 표현합니다. DB의 상태, report, GUI의 승인 배지가 같은 기준을 사용해야 합니다.
